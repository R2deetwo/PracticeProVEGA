Aria/ALOA bugs, property delete, and mobile polish

Context

ARIA and ALOA share one stack: [AloaProvider](src/contexts/AloaProvider.tsx), [AloaPanel](src/components/aloa/AloaPanel.tsx), [AloaChat](src/components/aloa/AloaChat.tsx) (label switches via useProduct().isProperty), and [MiniAloa](src/components/aloa/MiniAloa.tsx). There is no separate isAriaOpen flag today — bleed is a minimize vs close and toggle vs explicit close problem.

Recent pre-deploy work ([e0ffc6c](https://github.com/R2deetwo/PracticeProVEGA/commit/e0ffc6c)) already fixed property update id resolution and streaming UX; this plan targets delete, chat races, panel UX, dictation, splash, and BottomNav cleanup.

Task 1: Chat message ghosting / combined bubbles

Likely causes in [AloaChat.tsx](src/components/aloa/AloaChat.tsx)





No in-flight guard on handleSend (input disabled via isLoading, but race remains if stream continues after state flip).



Error path (L761) appends a new error message instead of replacing the streamMsgId placeholder → orphan/duplicate bubbles.



Stream fallback: empty stream result falls through to sendMessage on the same streamMsgId after partial chunks — can concatenate visually in one bubble.



isGeneratingRef only blocks history reload (L116), not concurrent sends.

Fix strategy





Add activeStreamRef with AbortController per send; abort prior stream on new submit.



Set isGeneratingRef true at send start; ignore duplicate submits until finally.



On error: map replace streamMsgId or filter placeholder — never append a second model row for the same turn.



On new send: remove prior empty content === '' model placeholders from aborted turns.



Mirror minimal fixes in [MiniAloa.tsx](src/components/aloa/MiniAloa.tsx) (same streamId pattern).

Task 5: Dictation / note-taker reliability

Primary surface: [SaveToNoteForm.tsx](src/components/forms/SaveToNoteForm.tsx) (embedded in AloaChat quick note).

Issues





processTranscription runs on an 8s interval immediately after isRecording flips true, often before getUserMedia + MediaRecorder finish (L182–186).



Tiny/empty blobs still call [transcribeAudio](src/services/geminiService.ts) → throws "Transcription failed." (L768).



Effect cleanup calls stopRecordingEngine on dependency churn → can stop recorder early.

Fix strategy





Gate recording engine: streamReadyRef set only after recorder.start.



Skip API if combinedBlob.size < MIN_BYTES (e.g. 2KB) or duration < 1s.



Debounce interval transcription (start after 3s of audio, increase interval to 10–12s).



Retry transcribeAudio up to 2 times with backoff; log structured error context.



User-facing copy: distinguish permission denied vs empty audio vs API failure.



Optional: reuse AloaChat live-session path only where appropriate — do not duplicate unnecessarily.
